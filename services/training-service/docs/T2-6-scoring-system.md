# T2-6 评分体系

AI 故障注入训练平台的综合评分系统，从 5 个维度对学员的排障表现进行量化评分，
给出总分、等级和详细评价，为训练效果评估提供客观依据。

## 背景与目标

### 为什么需要评分体系？

训练的核心目标是学习和提升，而评分是衡量学习效果的关键：

1. **量化能力**：把"排障能力"这个抽象概念变成可量化的分数
2. **激励学员**：有分数就有目标，激发学习动力
3. **客观公正**：多维度加权评分，避免主观偏见
4. **定位短板**：各维度得分对比，知道哪里需要加强
5. **进步追踪**：历史成绩对比，看到自己的进步
6. **排行榜**：增加竞技性和趣味性

### 评分原则

- **客观**：尽可能基于数据，减少主观判断
- **全面**：多个维度综合评估，不单一指标论英雄
- **公平**：同样的故障场景，同样的评分标准
- **可解释**：每个扣分都有原因，学员知道为什么扣分
- **激励性**：及格不难，优秀需要努力，鼓励持续提升

## 5 大评分维度

### 维度权重分布

### 详细说明

#### 1. 排障速度（30%）

**衡量指标**：从故障发生到完全恢复的总用时

**评分规则**：
- 在预期时间内完成 → 100 分
- 超过预期时间 → 线性扣分（实际用时 / 预期用时 × 100）
- 未恢复 → 0 分

**设计考量**：
- 排障速度是最直观的能力体现
- 权重最高，因为真实故障中"快速恢复"最重要
- 预期时间根据故障难度动态设置

#### 2. 恢复质量（25%）

**衡量指标**：T1-29 恢复验证得分

**评分规则**：
- 直接使用恢复验证得分（0-100）
- 10 项检查加权得分

**设计考量**：
- 恢复得快不等于恢复得好
- 需要验证系统是否真正恢复到正常状态
- 直接复用 T1-29 的结果，数据驱动

#### 3. 方法合理性（20%）

**衡量指标**：排障过程中使用的方法和步骤

**评分规则**：
- AI 评估 + 人工复核
- 考察点：
  - 是否按规范流程排障（信息收集→分析→假设→验证）
  - 是否使用了正确的工具和命令
  - 是否有无效操作（乱试一通）
  - 是否有破坏性行为（操作加剧故障）

**设计考量**：
- 结果重要，过程同样重要
- 引导学员养成良好的排障习惯
- 不是"修好了就是满分"，方法也要对

#### 4. 知识掌握（15%）

**衡量指标**：答题正确率、选择题得分

**评分规则**：
- 训练中的知识问答
- 故障原因分析选择题
- 技术概念理解题

**设计考量**：
- 不仅要会修，还要懂为什么
- 检验理论知识掌握程度
- 为进阶学习提供参考

#### 5. 团队协作（10%）

**衡量指标**：团队协作模式下的配合度

**评分规则**：
- 单人模式 → 默认 100 分
- 团队模式 → 评估分工、沟通、协作效率
- 考察点：
  - 任务分工是否合理
  - 沟通是否及时有效
  - 是否互相帮助
  - 团队整体恢复速度

**设计考量**：
- 企业中故障排障往往是团队协作
- 培养团队协作意识
- 权重不高，不影响单人训练体验

## HTTP API

### 4 个端点

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/scoring/calculate` | 执行评分 |
| GET | `/api/v1/scoring/result` | 获取评分结果 |
| GET | `/api/v1/scoring/dimensions` | 获取评分维度配置 |
| GET | `/api/v1/scoring/history` | 评分历史记录 |

### 评分流程

```
训练结束（或学员主动提交）
    ↓
收集评分数据：
  ├── 故障发生时间
  ├── 恢复时间
  ├── 恢复验证得分（T1-29）
  ├── 方法评估得分（AI/人工）
  ├── 知识答题得分
  └── 协作得分（团队模式）
    ↓
调用 POST /api/v1/scoring/calculate
    ↓
评分引擎计算：
  ├── 各维度分别计算
  ├── 加权求和得总分
  ├── 判定等级
  ├── 生成总体评价
  └── 保存记录
    ↓
返回评分结果
    ↓
前端展示：
  ├── 总分 + 等级徽章
  ├── 各维度得分雷达图/柱状图
  ├── 扣分明细
  ├── 总体评价
  └── 历史成绩对比
```

## 与上下游的关系

### 上游依赖
- **T1-29 故障恢复验证**：恢复质量得分的数据源
- **T2-7 AI 助手**：方法合理性评估（AI 评估操作过程）
- **T2-5 知识问答**：知识掌握得分的数据源
- **T2-10 协同排障**：团队协作得分的数据源

### 下游使用
- **T2-14 排行榜**：基于评分生成排行榜
- **T5-4 训练复盘报告**：评分数据进入复盘报告
- **T4-4 学员管理**：学员成绩档案
- **T3-2 课程推荐**：根据薄弱环节推荐学习内容

### 数据流向

```
恢复验证(T1-29) ──→ recovery_score
AI评估(T2-7) ─────→ method_score
知识答题(T2-5) ───→ knowledge_score
协作(T2-10) ──────→ collab_score
故障/恢复时间 ────→ speed_score
                        ↓
                  scoring.Service
                        ↓
                  评分结果 → 排行榜
                           → 复盘报告
                           → 学员档案
                           → 课程推荐
```

## 设计要点

1. **五维评估**：速度、质量、方法、知识、协作，全面评估
2. **数据驱动**：尽可能基于客观数据，减少主观判断
3. **加权评分**：不同维度权重不同，重要的占比高
4. **可解释性**：每个扣分都有原因，学员知道差在哪
5. **激励设计**：及格不难，优秀需要努力，有成长空间
6. **可配置**：维度和权重可以调整，适应不同训练场景
7. **历史记录**：保存历史成绩，追踪进步
8. **等级激励**：优秀/良好/及格/不及格，目标明确

## 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 评分不公平 | 学员不满 | 多维度+数据驱动，减少主观因素 |
| 权重不合理 | 评分偏差 | 根据训练数据持续调优权重 |
| 方法评估难量化 | 不准确 | AI初评+人工复核，逐步优化 |
| 只看分数不看过程 | 应试化 | 详细的扣分明细+改进建议 |
| 分数焦虑 | 学习压力 | 强调进步而非比较，鼓励成长 |

## 后续优化方向

1. **AI 智能评估**：用 AI 自动评估排障方法合理性
2. **个性化评分**：根据学员水平调整评分标准（新手宽容，高手严格）
3. **排行榜**：日榜/周榜/月榜，增加竞技性
4. **成就系统**：完成特定挑战获得徽章/成就
5. **进步追踪**：和自己的历史成绩对比，看到进步
6. **弱点分析**：分析薄弱环节，推荐针对性训练
7. **团队评分**：更精细的团队协作评分
8. **评分回放**：可以回看排障过程，对照评分学习
