# 注册与密码可见性升级（2026-10-29）

## 行为

当前 MVP 使用手机号或邮箱加密码注册，无验证码输入，也未接入短信或邮箱验证服务。修复手机号注册仍强制要求短信验证码的问题；保留账号格式、密码强度、重复账号检查、密码哈希及注册后登录。账号归属不因此被标记为已验证。

用户端登录、注册的密码及确认密码，管理端登录密码，均默认隐藏。点击眼睛按钮可独立显示或隐藏，按钮不提交表单；切换登录／注册后重新隐藏，输入值保留。

手机号注册验证由 `auth.registration_sms_required` 控制；MVP 的本地配置及 Helm `services.user-service.registrationSMSRequired` 明确为 `false`。代码在配置缺失时保留严格验证，后续需接入短信服务并补齐前端流程后再启用。短信免密登录不受此开关影响。

## 部署

无数据库迁移。本次同时更新 `user-service`、`web`、`admin`，并通过 Helm 下发注册策略。仅重建镜像无法更新服务器已有的 ConfigMap。

```bash
(
  set -euo pipefail
  export KUBECONFIG=/etc/rancher/k3s/k3s.yaml
  cd /data/src/quenching
  git pull --ff-only

  IMAGE_TAG=0.1.0 bash deploy/server/images.sh user-service web admin

  helm upgrade quenching ./deploy/helm -n platform \
    --reuse-values \
    --set services.user-service.registrationSMSRequired=false \
    --wait --timeout 10m

  kubectl -n platform rollout restart deployment/user-service deployment/web deployment/admin
  for service in user-service web admin; do
    kubectl -n platform rollout status deployment/"$service" --timeout=10m
  done
)
```

保留现有 release 的镜像标签、模型、存储等配置；以上沿用服务器此前使用的 `0.1.0` 镜像标签。

## 验收

1. 使用新的手机号注册，不填写验证码即可注册并登录；退出后可用相同账号密码登录。
2. 使用新的邮箱重复上述流程；已存在账号应显示“账号已注册”等实际业务错误。
3. 密码过短、缺少字母或数字、确认密码不一致时拒绝注册。
4. 登录及注册密码默认隐藏，眼睛按钮可显示／隐藏且不触发请求；密码和确认密码独立切换，登录／注册切换后恢复隐藏。
5. 管理端登录密码同样可切换；密码可见性不改变提交内容。

本地验证使用真实身份服务 handler、密码哈希与 JWT 配合内存仓储回归，以及浏览器模拟接口验证。服务器真实数据库、网关和注册后访问链路需部署后按以上步骤验收。
