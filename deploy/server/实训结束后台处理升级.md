# 实训结束后台处理升级（2026-10-29）

## 行为

- 点击“结束实训”或“退出”并确认后，保存最后一批操作记录，结束接口接受请求后返回“我的训练”；工作台不再轮询复盘或主动创建报告。
- 结束请求失败时停留工作台，显示错误并允许重试；两个结束入口共用提交锁，避免重复提交。离开工作台后的迟到响应不会把用户重新拉回历史页。
- 未生成报告记录的已结束实训也能显示后台进度；复盘记录建立后可进入详情查看实际生成状态。状态读取失败会显示未知，不伪装成尚未生成或已经完成。
- 后台根据数据库中持久化的结束状态继续收集操作证据、撤销故障、回收资源、评分和复盘。浏览器离开、刷新或关闭后不影响任务继续；服务重启后按持久化状态重试。

结束接口不再等待 AI 评分。大脑班次复用原有收尾协调器，旧版数据库项目增加后台调度，均在生成复盘快照前尝试评分，且仅对已完成并验证修复的训练计分。评分失败继续沿用原有尽力生成复盘和评分重试语义，不把“用户点击结束”当成故障已修复。评分按班次串行，正在被其他评分任务处理的班次会推迟生成快照，避免重复计分和过早生成报告。旧项目以已落库的结束时刻作为后台调度依据。

工作台先等待最后一批操作上报确认，随后提交结束请求；已有在途批次也会等待并排空，保存失败时保留重试。实际终端、文件、工具执行的服务端证据仍按后台审计封存流程收集。资源回收及报告生成不是接口返回时已完成的保证，失败和待重试状态通过历史记录及服务日志追踪。训练记录支持按已结束状态分页，较早的待处理班次不会因只有最近20条而失去入口。

所有结束结果在生成报告快照前都会检查操作记录是否已同步，主动退出或未修复的训练也适用。同步暂未完成时由后台重试；达到原有审计封存期限后，可带明确的记录缺口继续生成报告，不能把缺失的证据视为完整记录，也不会因同步服务不可用无限等待。

## 部署

本次无数据库迁移，需同时更新 `training-service` 和 `web`。沿用平台标签 `0.1.0`，无需因本次改动重建商城业务镜像。

```bash
(
  set -euo pipefail
  export KUBECONFIG=/etc/rancher/k3s/k3s.yaml
  cd /data/src/quenching
  git pull --ff-only

  IMAGE_TAG=0.1.0 bash deploy/server/images.sh web training-service

  kubectl -n platform rollout restart deployment/training-service deployment/web
  for service in training-service web; do
    kubectl -n platform rollout status deployment/"$service" --timeout=10m
  done
)
```

若尚未部署上一轮源码工作区改动，先按 [源码工作区与终端目录升级](源码工作区与终端目录升级.md) 完成商城 `mall-0.2.0` 镜像与模板升级，再执行本页新增的 training-service 更新。不要仅更新前端后删除其旧版项目报告触发，而继续运行旧后端。

## 验收

1. 结束一次真实实训，确认结束接口接受后即返回“我的训练”，没有“等待复盘”阻塞，也没有浏览器请求 `/reviews/generate`。
2. 故意让结束接口失败，页面应保留且可以重试；重复点击两个结束入口只产生一份请求。
3. 结束接受后关闭浏览器，检查 sandbox-service/故障引擎日志与 namespace/PVC 回收，再次登录可看到报告或实际后台状态。
4. 复盘暂未建立时保留本次训练记录；生成中与已完成由报告实际状态决定。复盘服务不可用时显示状态读取错误，恢复后能刷新继续。
5. 在测试环境重启 training-service，确认数据库中的待收尾训练继续处理；复盘生成接口按班次幂等，不创建重复报告。
6. “退出”以未完成训练处理，不能因主动退出而获得已修复的评分；复盘仍按既有未完成训练语义生成。

本地验证包含服务层与前端回归、后台重试与恢复、评分顺序、真实浏览器交互（模拟接口）。真实数据库并发、k3s资源回收、模型服务与整条后台链路仍需服务器验收。
