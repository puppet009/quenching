# 日志、前端与数据库时间统一（2026-10-18）

## 2026-10-19：前端显示跟随用户时区

web/admin 默认使用页面加载时浏览器的 IANA 时区：国内显示北京时间，海外显示当地时间，历史日期按对应时刻的夏令时规则转换。设备时区更改后刷新页面即可生效。日志面板显示当前时区；单条日志详情与悬浮提示附带该事件的 UTC 偏移，区分夏令时结束时重复出现的小时。日志正文保留原文。

服务器校时继续提供准确的当前时刻，时区只决定显示方式。数据库、接口时间戳、训练时长和评分判断不受用户时区影响。服务器日志文件仍按其已配置的 Asia/Shanghai 时区组织，记录保留时区偏移；这不决定前端页面的显示时区。

如果已经完成下述日志升级，本次只需重建两个前端镜像并重启；现有镜像 tag 非 0.1.0 时，构建须传入与部署一致的 IMAGE_TAG：

```bash
(
  set -euo pipefail
  export KUBECONFIG=/etc/rancher/k3s/k3s.yaml
  cd /data/src/quenching
  git pull --ff-only
  bash deploy/server/images.sh web admin
  kubectl -n platform rollout restart deployment/web deployment/admin
  kubectl -n platform rollout status deployment/web --timeout=5m
  kubectl -n platform rollout status deployment/admin --timeout=5m
)
```

本次通过 30 项前端测试及两个前端的 TypeScript/Vite 生产构建。浏览器使用本地验收数据，在上海、洛杉矶、UTC、加德满都四个时区分别验证 web/admin；覆盖跨日、夏令时重复小时偏移、日志原文、图表、页面交互和错误电脑时钟下的服务器校时。真实服务器部署待现场验收。

## 2026-10-18 日志升级范围（含最新显示规则）

- 八个后端日志继续同时写 stdout 与根目录 logs；部署失败保留超时原因和清理前诊断。
- web/admin 页面、图表、告警、复盘和历史记录统一按浏览器当地时区显示。接口和存储保留带时区的实际时刻或 Unix 毫秒值。
- 两个页面首次加载、前台每分钟及重新切回页面时通过 `/api/v1/client/time` 校时。成功后用服务器时刻及 performance 单调时钟推进；过滤超过 5 秒的校时响应，始终输出整数毫秒。首次校时晚于业务数据返回时，相对时间标签也会自动刷新。失败不阻塞页面，保留已有校时或本地时钟兜底。
- 实训页面按后端开始时间计算已用时长，刷新或后台标签节流后恢复；班次截止、故障触发、沙箱回收和评分仍由后端决定。
- 未捕获 JS、Promise、React 错误、已有 console.error 路径（含终端连接错误）以及统一请求层的网络/5xx 异常上报网关。console.error 保留原输出，采集时仅选取 Error 或文字，不序列化任意对象参数。每页最多每分钟 5 条，窗口内去重，失败不递归上报、不无限重试；前后端都过滤常见凭证和 URL 查询串。接口仅接受固定字段，限制请求体 12KiB，并沿用网关 IP 限流。预期业务 4xx 不作为运行异常收集。
- NGINX 使用带时区的 JSON 访问日志，JSON 访问日志路径使用 `$uri`，不加入请求查询串、正文或认证头。错误输出经采集器过滤查询串和常见凭证后落盘，保留 upstream 连接失败等原因。Go 访问日志也过滤查询参数中的凭证，不修改用于实际认证的请求。两个前端镜像安装时区数据并设置 Asia/Shanghai。
- PostgreSQL 容器时区、SQL 会话 TimeZone、日志 log_timezone 明确为 Asia/Shanghai。TIMESTAMPTZ 保持原有存储语义，不重写历史行、不将数据整体平移 8 小时。平台连接池也明确设置会话时区。
- 每个 Linux 节点部署 Vector log-agent，补齐 web/admin、PostgreSQL、Redis、RabbitMQ、Prometheus 的 stdout/stderr 文件留存；不重复采集已有后端文件日志，不采集 sandbox-* 业务日志。后者仍属于现有实训 Loki/日志证据链，避免与平台运维日志混在一起。

## 目录与保留规则

```text
quenching/
├── services/
├── apps/
└── logs/
    ├── api-gateway/2026-10-18/api-gateway-<pod>.log
    ├── sandbox-service/2026-10-18/sandbox-service-<pod>.log
    ├── ai-service/2026-10-18/ai-service-http-<pod>.log
    ├── ai-service/2026-10-18/ai-service-grpc-<pod>.log
    ├── web-browser/2026-10-18/web-browser-<网关pod>.log
    ├── admin-browser/2026-10-18/admin-browser-<网关pod>.log
    ├── web/2026-10-18/web-<pod>-21.log
    ├── admin/2026-10-18/admin-<pod>-21.log
    ├── postgresql/2026-10-18/postgresql-<pod>-21.log
    ├── redis/2026-10-18/redis-<pod>-21.log
    ├── rabbitmq/2026-10-18/rabbitmq-<pod>-21.log
    ├── prometheus-server/2026-10-18/prometheus-server-<pod>-21.log
    └── .collector/<节点名>/    # 文件读取检查点，勿手工清空
```

八个后端与浏览器异常：单文件 100MB，最多 7 个大小轮转副本，清理超过 30 天的本服务日志。NGINX/基础组件：按北京时间日期和小时分文件，每小时检查并清理超过 30 天的采集日志；这类文件采用按时分卷，不承诺 100MB 大小轮转。清理不递归删除、不删除无关文件。

采集 JSON 的 ts 是 CRI 事件时间转换后的北京时间，timestamp 保留原始时刻；message 除 web/admin 的凭证过滤外保留原文。原文内第三方组件自己生成的 UTC 时间不做字符串改写。PG 自身日志已明确配置北京时间。文件收集沿用 stdout/stderr，不要求 PostgreSQL 再打开自身文件采集器。log-agent 自身诊断使用 `kubectl logs ds/quenching-log-agent -c log-agent`，避免采集器错误递归写回自身。

hostPath 日志属于各节点本地目录，单机即 `/data/src/quenching/logs`；多节点并不会自动合并。新节点须事先准备同路径和 UID/GID 10001 权限，并分发平台镜像。需要集中存储可改为 RWX PVC；RWO 卷不能作为多节点共享方案。已有日志 PVC 不删除、不自动复制旧卷文件。

## 现有服务器升级

在没有进行中实训的维护窗口执行。脚本先构建并验证全部镜像，再调整数据库；首次设置容器 TZ 或关闭已有 PG logging_collector 时会滚动重启 PostgreSQL，有短暂连接中断。脚本不迁移业务表、不清空数据库、不重建 mall 镜像，复用 release 的现有密钥及配置。

```bash
(
  set -euo pipefail
  export KUBECONFIG=/etc/rancher/k3s/k3s.yaml
  cd /data/src/quenching
  git pull --ff-only
  bash deploy/server/upgrade-observability.sh
)
```

镜像默认 tag 0.1.0，现有 tag 不同须传入 IMAGE_TAG；私有镜像仓库沿用既有构建与分发流程。不要用首装 values-server.yaml 的占位密钥覆盖生产 release。prepare-logs.sh 只准备根目录 logs，不递归修改仓库权限。

11 个镜像为七个 Go 服务、ai-service、web、admin、log-agent。log-agent 固定 Vector 0.59.0，镜像构建时执行配置校验与四项转换测试，失败则不会进入统一导入步骤。采集器读节点 /var/log/pods，只有 Pod/Node/Namespace 的读取权限；没有 Secret/数据库写权限。源日志挂载只读，输出挂载到 logs。

配置属主：共享时间/异常采集位于 packages/shared，网关接收位于 api-gateway，数据库连接默认值和独立日志 sink 位于 go-common，节点采集器和部署工具位于 deploy。没有把业务实现放入前端页面或其他业务域。

## 升级后验收

脚本等待 PostgreSQL、十个应用 Deployment 和 log-agent DaemonSet 就绪。数据库时区或 stderr 配置未生效时停止，不报告成功。人工进一步检查：

```bash
kubectl -n platform exec postgresql-0 -c postgresql -- psql -U quenching -d quenching \
  -c 'SHOW timezone' -c 'SHOW log_timezone' -c 'SHOW logging_collector' -c 'SELECT now()'
kubectl -n platform logs ds/quenching-log-agent -c log-agent --tail=80
find logs -maxdepth 3 -type f -name '*.log' -print
```

打开 web/admin 后应出现 NGINX 访问日志；浏览器异常目录在第一条真实异常上报后产生。改变电脑时区并刷新页面后，绝对时间应转换为当地时间；改变电脑时钟后成功校时仍应查询服务器附近的指标与日志窗口。浏览器错误详情、网址查询串不应出现在认证或业务数据中。
