## 升级

使用现有部署 tag（默认 `0.1.0`）重新构建 **api-gateway、content-service、sandbox-service、web**，并升级 Helm Chart。
内容域提供登记封面的只读图片接口，网关增加该图片专用路由；两个模板消费服务包含目录与注册表，web 包含新的详情布局。
只更新前端或只拉取源码无法更新页面上的模板名称和简介。

```bash
(
  set -euo pipefail
  export KUBECONFIG=/etc/rancher/k3s/k3s.yaml
  cd /data/src/quenching
  git pull --ff-only

  IMAGE_TAG=0.1.0 bash deploy/server/images.sh api-gateway content-service sandbox-service web

  helm upgrade quenching ./deploy/helm -n platform \
    --reset-then-reuse-values --wait --timeout=10m

  for service in api-gateway content-service sandbox-service web; do
    kubectl -n platform rollout restart deployment/"$service"
    kubectl -n platform rollout status deployment/"$service" --timeout=10m
  done
)
```

若实际部署使用其他 tag，将命令中的 `IMAGE_TAG` 与现有镜像 tag 保持一致。
本次无需数据库迁移、重新构建 mall 业务镜像或重新验收故障：`template.yaml`、mall 模板 Chart、业务源码与运行制品指纹算法均未修改。
如果尚未完成日志/时间升级，直接运行 `upgrade-observability.sh` 也会构建最新全部平台镜像并升级 Chart，包含本次展示变更，无需再单独执行本节构建。

1. 刷新项目大厅，标题为“mall 电商交易实训”，简介介绍真实开源商城与排查训练。

4. 如果启动请求失败，按钮应提示重试；不确定的请求仍复用同一班次，避免重复申请。

有登录 token 时，可检查 `GET /api/v1/templates`：mall 应包含 `cover`、`overview`、`audience`、`business_scenarios`、`learning_objectives` 及服务展示资料。

旧模板未提供 `catalog.yaml` 时继续使用原有信息。无效展示资料会记录 warn 并回退到清单资料。
